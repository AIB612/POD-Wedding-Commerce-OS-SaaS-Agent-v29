二、A. 客户聊天 Agent（server/pod-agent/customer/*）
--------------------------------------------------------------------------------

  流程（详见标准文档第 9 章）：
    消息 → 护栏（guardrails.js）→ 语言/意图/实体识别（nlu.js）
         → 路由（router.js，置信度 ≥ 0.6 本地回答）
         → 本地：规则回答 + 店铺工具（tools.js，10 个工具）
         → 低置信度且配置了模型密钥：LLM（customer/llm.js，只能调工具）
         → 无密钥：最佳本地答案 + “转人工”
  工具（CUSTOMER_TOOLS）：search_knowledge、get_policy、get_product、
    recommend_products、quote_shipping、find_order、get_tracking、
    check_discount_code、issue_discount、handoff_to_human。
  报价 = 结账价（quoteStorefront）；查单需订单号 + 下单邮箱。
  后台：Admin → “AI 客服 / Chat agent”（/api/saas/agent/*，15 项 KPI）。
  公开状态：GET /api/pod-agent/status →
    { ok, strategy:"local_first", mode, confidence_threshold:0.6,
      kpis:15, tools:10, languages:{detected:[en,zh,de,fr,it], replies:[en,zh,de]} }
  线上 mode = "rules"（生产未配置模型密钥）。

三、B. 后台运营 Agent（server/services/agent-ops-service.js）
--------------------------------------------------------------------------------

  入口：POST /api/agent/ops（requireAdmin：管理员登录会话或 x-admin-api-key）。
  Admin 页面里的 “AI …” 按钮、结算、外联等都把一句命令发到这里。

  意图（关键词匹配，按顺序）：
  | 关键词                        | 意图       | 读取 / 动作                         |
  |-------------------------------|------------|-------------------------------------|
  | 同步/sync/商品                | catalog    | products；含“上架/push/发布/同步到” |
  |                               |            | → 建 product_list 任务，否则建      |
  |                               |            | catalog_sync 任务                   |
  | 广告/营销/roas/campaign       | marketing  | marketingSummary + optimizationIdeas|
  |                               |            | 含“创建/投放/预算…” → campaign_publish|
  | 会话/inbox/消息/客服          | inbox      | conversations + messages；含“回复” |
  |                               |            | → cs_reply 任务                     |
  | 达人/influencer/creator       | creator    | discoverInfluencers；含“联系/合作” |
  |                               |            | → influencer_outreach 任务          |
  | 财务/利润/成本/margin         | finance    | financeSummary                      |
  | 客户/画像/segment/推荐        | customer   | customerProfiles                    |
  | 订单/物流/shipment/order      | operations | orders + shipments（只读）          |
  | 任务/task                     | tasks      | tasks                               |
  | 其他                          | overview   | overview                            |

  返回 { intent, plan, data, guardrails:{ writes_require_approval,
         external_messages_require_approval, budget_increases_require_approval } }。
  不调用任何 LLM。

  审批：
    · 写操作只“创建任务”（collection tasks），不直接执行。
    · POST /api/saas/tasks/:id/approve（需 requireApproval：请求体
      approved:true 或头 x-action-approved: true）只把任务状态改为 approved。
    · executeApprovedTask() 在代码里存在（product_list 推送 Shopify、cs_reply、
      order_fulfill 只记录），但目前没有任何路由或定时任务调用它——
      审批后不会自动执行。
    · operations 意图仍按旧状态 “Paid / Production” 统计待发货；网站订单
      现用 “Needs approval / Proof ready / Approved / Production / Ready to ship /
      Label created / Shipped / Delivered”，因此该计数可能为 0（已知差异）。

四、C. 旧版通用入口 /api/agent/chat（server/orchestrator.js）
--------------------------------------------------------------------------------

  仍挂载在 server/routes/public.js（限流 30 次/分钟），但网站页面已不调用
  （首页用 /api/pod-agent/chat）。逻辑：
    · 管理员且命中运营关键词 → runOpsCommand（同第三节）
    · 其他 → rag.js 词法检索 server/data/knowledge.json → callLLM
      （server/connectors/llm.js）；未配置模型时返回 fallback:true
  保留仅为兼容；新功能不要接在这里。

五、LLM 配置（两套调用，同一组环境变量）
--------------------------------------------------------------------------------

  LLM_PROVIDER=openai|chatgpt|anthropic|gemini|deepseek|grok|xai
  OPENAI_API_KEY / OPENAI_MODEL      ANTHROPIC_API_KEY / ANTHROPIC_MODEL
  GEMINI_API_KEY / GEMINI_MODEL      DEEPSEEK_API_KEY / DEEPSEEK_MODEL
  XAI_API_KEY / XAI_MODEL            LLM_TIMEOUT_MS
  · 客户聊天 Agent（customer/llm.js）：openai / chatgpt / xai / deepseek 支持工具
    调用；anthropic / gemini 只回答开放问题。
  · 旧入口 C 用 connectors/llm.js；Studio 设计描述（generate-design）用
    server/pod-agent/ai.js。
  · 生产当前未设置任何模型密钥 → 全部规则模式。

  Agent Card：GET /.well-known/agent-card.json（ENABLE_A2A_AGENT_CARD=false 关闭）。

六、安全边界（由代码强制）
--------------------------------------------------------------------------------

  1. 客户通道只用客户安全工具；不返回其他客户、成本、利润、密钥名称。
  2. 订单信息只在订单号 + 下单邮箱一致时显示；15 分钟内同一订单号失败 5 次锁定。
  3. 后台写操作必须带审批标记；运营 Agent 只建任务。
  4. 外部消息、预算、发布、退款不由 Agent 自动执行。
  5. 限流：/api/pod-agent/chat 30 次/分钟；/api/agent/chat 30 次/分钟。
  6. /pod-agent/ 下只公开 widget.js，其余 404。
